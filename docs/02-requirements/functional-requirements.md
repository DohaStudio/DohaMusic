# 기능 요구사항

> 문서 목적: MVP 기능을 추적 가능한 요구사항으로 정의한다.
> 현재 상태: **Phase 6 Lyrics AI 반영 / DohaLM 연동 [계획]**
> 최종 수정일: 2026-08-05

| ID | 요구사항 | 상태 |
|---|---|---|
| FR-001 | 프롬프트 또는 직접 작성 가사를 입력한다. | [Foundation 완료] |
| FR-002 | 장르, 분위기, BPM, 곡 길이, Seed를 선택적으로 지정한다. | [부분 완료: 장르·곡 길이·Seed] |
| FR-003 | 유효한 요청으로 비동기 생성 작업을 만든다. | [Foundation 완료: 내부 Mock Worker] |
| FR-004 | 사전학습 모델로 노래를 생성한다. | [검증 필요] |
| FR-005 | 생성 음원에서 보컬과 반주를 분리한다. | [기술 완료: Mock·HTDemucs, 청취 평가 필요] |
| FR-006 | 동의가 유효한 참조 음성을 업로드하고 음성 프로필을 만든다. | [부분 완료: 동의 확인 메타데이터] |
| FR-007 | 분리 보컬의 음색을 선택한 프로필로 변환한다. | [검증 필요] |
| FR-008 | 보컬과 반주를 재결합하고 보컬·반주·전체곡을 출력한다. | [계획] |
| FR-009 | WAV 저장과 선택적 MP3 변환을 제공한다. | [부분 완료: 생성·Stem WAV 저장] |
| FR-010 | 상태, 진행률, 오류, 취소, 재시도를 제공한다. | [부분 완료: 상태·오류 조회] |
| FR-011 | 이력에서 설정·모델·버전·Seed·파일을 확인한다. | [부분 완료: 요청·Seed·파일 메타데이터] |
| FR-012 | 주제·분위기·장르·키워드로 구조화된 가사 초안을 생성한다. | [완료: Template·Mock] |
| FR-013 | 직접 작성 가사를 정규화하고 구조·길이·반복·태그를 검증한다. | [완료] |
| FR-014 | DohaLM을 호출하여 프롬프트 기반 가사 초안을 생성한다. | [계획] |
| FR-015 | 사용자가 입력한 기존 가사를 DohaLM으로 분석한다. | [계획] |
| FR-016 | 가사의 주제·구조·운율·음절 수·반복 구간을 분석한다. | [계획] |
| FR-017 | 분석 결과를 바탕으로 수정안·제목·콘셉트 제안을 생성한다. | [계획] |
| FR-018 | AI 최초 생성본과 사용자 수정본을 별도 불변 버전으로 저장한다. | [계획] |
| FR-019 | 사용자가 가사를 직접 수정하고 최종 승인한다. | [계획] |
| FR-020 | 승인되지 않은 AI 초안과 수정 제안을 음악 생성에 사용하지 않는다. | [계획] |
| FR-021 | 모델명·모델 버전·생성 설정·프롬프트와 모델 manifest 식별자를 기록한다. | [계획] |
| FR-022 | 사용자 수정 이력과 최종 승인 시각을 기록한다. | [계획] |
| FR-023 | 상업 작업에는 상업 이용 검토 상태가 `commercial_approved`인 모델만 사용한다. | [계획] |
| FR-024 | 연구용 모델과 상업용 모델을 구분하고 연구용 결과의 상업 Pipeline 전달을 차단한다. | [계획] |

검증 가능한 행위는 [인수 기준](acceptance-criteria.md), API는 [API 개요](../06-api/api-overview.md)에 매핑한다.

`Foundation 완료`와 `부분 완료`는 전체 제품 기능 완료를 의미하지 않는다. ACE-Step, HTDemucs, Seed-VC는 선택적 실험 Provider이며 사용자 청취 평가가 남아 있다. Lyrics Template은 실제 LLM이 아니며 사용자 품질 평가가 필요하다. FR-014~024는 설계 요구사항이며 구현·API·migration 검증이 없다. DohaLM의 Python SDK와 전용 Lyrics API도 아직 확정되지 않았다. MP3·인증은 구현하지 않았다.

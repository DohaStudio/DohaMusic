# ADR-003: 비동기 작업 처리

> 문서 목적: 장시간 생성을 비동기 작업으로 처리하는 결정을 기록한다.
> 상태: **승인 제안**
> 현재 상태: 초기 설계

## 배경

음악 생성은 오래 걸리고 GPU 오류·취소·재시도가 필요해 동기 HTTP 요청 수명에 맞지 않는다.

## 결정

요청은 작업을 생성하고 즉시 작업 ID를 반환한다. Worker가 단계별로 처리하며 사용자는 상태 API를 조회한다.

## 선택 이유와 대안

동기 처리보다 타임아웃과 자원 제어가 명확하지만 큐, 상태 전이, 멱등성 운영 부담이 생긴다. 초기 DB 큐에서 Redis 기반 큐로 교체 가능하게 한다.

## 영향

[작업 상태 모델](../07-database/job-state-model.md), lease, heartbeat, 취소와 새 작업 기반 재시도가 필요하다.

## 재검토 조건

운영 규모와 신뢰성 요구가 DB 큐 한계를 넘거나 별도 워크플로 엔진이 필요한 경우 재검토한다.
